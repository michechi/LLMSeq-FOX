**Status:** interim (Steps 1–5 complete; Step 6 decision branches drafted).
**Last updated:** 2026-04-21.
**Scope:** `data/simulation/tested/{X,y}_{train,val,test}_{6,9,test_just_pair}.csv`

## 1. Executive summary

- **Tricky collapses to lag-aware pair detection.** A linear logistic
  regression on the 676-dim aggregated lag-pair count vector
  $g_{ab}^{(\lambda)}(X)=\sum_t \mathbf{1}[X_t=a,\,X_{t+\lambda}=b]$
  reaches **AUC 0.997** on `_6` (“Tricky Det.”) and **AUC 0.671** on
  `_9` (“Tricky Random”) — matching the paper’s theoretical ceiling
  $\text{AUC}^*=0.670$ at $\pi=0.3$ **exactly**. No neural model in the
  paper beats this.
- **The paper’s contiguous-$k$-gram baseline was the wrong baseline.**
  It fails because it does not know $\lambda=7$. A $\lambda$-aware
  bigram saturates the task. The encoder-vs-decoder gap reported in
  Figure 1 is therefore a gap on a **local-shortcut task**, not on a
  global-integration task.
- **Held-out-rule: C1 lag-pair features are rule-specific, not rule-general.**
  On synthetic data with fresh $(S,\kappa,\lambda)$, logistic regression
  on $g_{ab}^{(\lambda)}$ achieves AUC 1.0 **within a rule** and
  AUC ≈ 0.5 **across rules**. So the task is literally “pick the right
  26×26 weighting.”
- **Parity’s bottleneck is hidden-subset identification, not parity.**
  Feed the network the membership bits $b_t=\mathbf{1}[X_t\in K]$ and
  a 20→64→1 MLP reaches AUC **0.997** in ~52 s. Give it per-key parities
  and it reaches **1.000**. The same architecture on raw letters stays
  at chance. The paper presents parity as a global-integration
  failure; our decomposition shows the architecture/supervision can do
  parity, but cannot jointly infer $K$ and apply parity from
  end-to-end supervision.
- **`_6` and `_9` use different label rules.** Phase 1b inspects
  weights on the 676-dim lag-pair LogReg (AUC 0.997 on `_6`). On
  `_6` the weight pattern is the *unsigned* indicator of
  $(a,b)\!\in\!S\!\times\!S$ (both κ-ordered and κ-reversed pairs get
  weight ≈ +9); on `_9` the weights split cleanly by κ ordering (+1.1
  for ordered, −0.28 for reversed). So **`_6` is “exists lag-λ pair
  in S, ignore κ”**, **`_9` is paper Def.1 (“exists lag-λ ordered
  pair”) with $\pi=0.3$**. The paper narrative — that Det. and
  Random differ only in the noise level applied to the same rule —
  is contradicted by the data.
- **Oracle ceilings do not match the paper claim for `_6`.** The
  paper lists `_6` as Tricky Det. with $\rho=0.293$, $\pi=0$,
  $\text{AUC}^\*=F_1^\*=1.0$. Stored $\rho=0.356$. The best single
  rule reaches oracle $F_1=0.855$, not 1.0. Phase 2 / 1b show the
  rule is linearly expressible in lag-pair counts with AUC 0.997,
  implying near-deterministic labels — the paper ceiling is simply
  for a different rule than the one actually generated. `_9`
  matches its reported ceiling to three decimals.
- **Paper’s S differs from the implementation’s S.** The paper states
  $S=\{W,D,Q,J,X,U\}$; the data-generation code
  (`src/data/parity_variants.py`, `simulation/signal_decomposition.py`,
  `simulation/test_simulation_odd_*.py`) uses $S=\{W,D,Q,J,X,N\}$ for
  parity and $S=\{W,D,Q,J,X,U\}$ for `_6`/`_9`. Parity with the paper
  S gives 51 %; parity with the impl S gives 100 %.
- **Verdict.** (A) Smaller honest paper is supported **today**. Claim:
  “encoder-based architectures learn hidden *fixed-lag skip-pair* rules
  more efficiently than decoder-only ones; under noise the gap widens
  but vanishes at scale.” (B) The stronger claim (“global sequential
  integration”) requires a redesigned task. Section 8 prototypes one.

`analysis/mechanism_id/{results,plots,scripts}/`.

## 2. Exact implemented label rules

### 2.1 Parity (dataset tag `test_just_pair`)

Generated by `simulation/test_simulation_det.py:744` calling
`get_key_letters_parity(seq, letters_4_key)` (see lines 719–735 of the
same file) and saved at line 770. Independent verification code lives
in `src/data/parity_variants.py:305`.

Formally, on tokens $X_1,\dots,X_n$ with $n=20$:

$$
Y^* \;=\; \mathbf{1}\!\Bigl\{
  \bigl|\{k\in K : N_k(X)\text{ is even}\}\bigr| \equiv 0\pmod 2
\Bigr\},\qquad
K=\{W,D,Q,J,X,N\}.
$$

Using parity-of-even-counts in a subset of size $m=6$ (even), this
equals parity of the **total** key-letter count:

$$
Y^* = \mathbf{1}\!\Bigl\{ \sum_{k\in K} N_k \equiv 0 \pmod 2\Bigr\}.
$$

Empirical check (Phase 1, `results/phase1_label_audit.csv`): rule
`parity_total_count_S_impl` matches stored labels **100 %**, all three
splits, using `S = {W,D,Q,J,X,N}` — **NOT** `{W,D,Q,J,X,U}` as the
paper says. Paper-S gives 51.7 %.

### 2.2 Tricky (tags `_6`, `_9`)

Label generator lives in `simulation/do_assign_outcome_pos.py:12`
(`assign_outcome_positional`, default `tolerance=True`,
`min_chain_length=2`) with chain extraction in
`simulation/do_check_lag.py:3` (`check_lag`, greedy, exact-λ spacing).
Several other variants exist (`do_assign_outcome_pos_4.py` adds a
“second key even” AND, `test_simulation_odd_*.py` mixes length-20 and
length-21 sequences and inverts parity for odd lengths).

Paper Definition 1 is

$$
Y^* = \mathbf{1}\!\bigl\{\exists (t_1,\dots,t_k),\, k\ge 2,\,
  t_{j+1}-t_j=\lambda,\,
  X_{t_j}\!\in\!\mathcal{S},\,
  \kappa(X_{t_1})\le\!\cdots\!\le\kappa(X_{t_k})\bigr\}.
$$

**With $k\ge 2$, this is equivalent to “exists one pair
$(t,t+\lambda)$ at spacing $\lambda$ with both tokens in $\mathcal{S}$
and $\kappa(X_t)\le\kappa(X_{t+\lambda})$.”** Any longer compliant
chain implies at least one such pair.

Observations (Q1 answers):

1. **`_9` = paper Def.1 with κ constraint.** Best rule
   `greedy_tol0_min2_S_paper` hits accuracy 0.699 (stored), oracle AUC
   0.670, F1 0.578, matching the paper’s claimed
   $(\text{AUC}^\*,F_1^\*) = (0.67,0.58)$ to three decimals. Rule
   $\rho = 0.293 = (0.416-0.3)/(1-0.6)$ back-solves to the paper’s
   stated $\rho^\*=0.293$.
2. **`_6` labels IGNORE the $\kappa$ ordering.** Phase 1b (§2.4,
   `results/phase1b_rule_check.txt`) fits LogReg on the 26×26
   aggregated lag-pair features and inspects weights directly:
   - Top-25 positive (a,b) weights on `_6` have all 25 pairs
     $(a,b)\in S_\text{paper}\times S_\text{paper}$ with weight
     between **+7.0 and +9.9**, then a ~9× gap to the next weight
     (+0.08). Crucially the set includes both κ-ordered pairs (W→U,
     weight +9.263) AND reverse-ordered pairs (U→W, +8.296; J→D,
     +7.665; Q→W, +8.487; U→D, +7.674).
   - On `_9` the same test returns **signed** weights: ordered pairs
     are positive (D→Q +1.132, W→J +1.068, J→X +1.057, …) and
     reverse-ordered pairs are negative (Q→W −0.285, J→D −0.275,
     U→D −0.263, U→Q −0.256, …).
   So **the two datasets use DIFFERENT rules**:
   - `_9` ≈ paper Def.1 (pair in $S$ with monotone $\kappa$), $\pi=0.3$.
   - `_6` ≈ **pair in $S$ with NO $\kappa$ constraint**, i.e., the
     paper Def.1 stripped of condition (iii), labeled
     (near-)deterministically.
   Both use the paper $S=\{W,D,Q,J,X,U\}$.
   This directly contradicts the paper’s “same rule, different
   noise” reading of Tricky Det. vs. Tricky Random.
3. **Parity** is the impl $S=\{W,D,Q,J,X,N\}$ (not paper’s U).
   For $|K|=6$ even, total-count parity is identical to paper Def.4,
   so the paper-level claim is correct although the code uses a
   different letter. Paper $S$ gives 51.7 %, impl $S$ gives 100.0 %.

### 2.4 Phase 1b — rules inferred from LogReg weights

Feature: 676-dim aggregated lag-pair count $g_{ab}^{(\lambda=7)}$.
LogReg AUC on `_6` = **0.997**, on `_9` = **0.671**.

On `_6`, marginal letter ranking (sum over rows + columns):

```
J +73.8   U +72.4   Q +71.8   D +70.2   W +69.1   X +???
(next best letter: A, G, E, C, N at about −17)
```

Huge gap after the 5 (X implied via column counting; see
`phase1b_logreg_weights.csv`). This is exactly $S_\text{paper}$.

The top-25 positive weights are a Cartesian square
$S_\text{paper}\!\times\!S_\text{paper}$, unsigned w.r.t. $\kappa$.
On `_9` the SAME 5 letters dominate marginals, but the weights are
signed by $\kappa$ direction.

So the mechanism is simple and linear in this feature space:

$$
\hat Y_{\_6} = \mathbf{1}\Bigl\{\sum_{a,b\in S}\! g_{ab}^{(\lambda)} \ge \tau\Bigr\},\qquad
\hat Y_{\_9} = \mathbf{1}\Bigl\{\sum_{\substack{a,b\in S \\ \kappa(a)\le\kappa(b)}}\!\! g_{ab}^{(\lambda)} - \sum_{\substack{a,b\in S \\ \kappa(a) > \kappa(b)}}\!\! g_{ab}^{(\lambda)} \ge \tau'\Bigr\}.
$$

Both fit comfortably inside the baseline ladder’s C1 family and fit
with 676 parameters + one threshold. Nothing sequential, nothing
global.

Counterexamples (50 each) are in
`results/phase1_counterexamples.csv`.

## 3. Baseline ladder on standard evaluation (Q2, Phase 2)

Feature families (see `scripts/common.py`):

- **A1** full 26-dim letter counts `feat_count26`
- **A2** 6-dim key-letter counts `feat_count_key`
- **B** residue-class counts mod λ: 26 × λ = 182 dims `feat_residue`
- **C1** aggregated 26×26 lag-pair counts `feat_lag_pair`
- **C1k** aggregated 6×6 lag-pair counts (key-only)
- **C2** position-aware lag-pair indicators (sparse CSR,
  (n−λ)×26×26 = 8788 dims) `feat_lag_pair_position_sparse_row`
- **D1k** aggregated lag-trigram counts (key-only, 6³ dims)
- (E – symbolic recognizer not needed: C1 already saturates.)

Primary metric: AUC on the held-out test split. Models: L2 LogReg (`lbfgs`), XGBoost (`tree_method=hist`).

### 3.1 Standard-split AUC (`results/phase2_ladder_standard.csv`)

| family | dim | `_6` LogReg | `_6` XGB | `_9` LogReg | `_9` XGB |
|---|---:|---:|---:|---:|---:|
| A1 count26              | 26   | 0.816 | 0.815 | 0.584 | 0.579 |
| A2 key count            | 6    | 0.773 | 0.772 | 0.575 | 0.573 |
| B residue mod 7         | 182  | 0.818 | **0.938** | 0.582 | 0.608 |
| **C1 lag-pair 26×26**    | 676  | **0.997** | **0.997** | **0.671** | 0.670 |
| C1k lag-pair key-only   | 36   | 0.846 | 0.846 | 0.629 | 0.630 |
| C2 lag-pair position (sparse) | 8788 | 0.996 | 0.996 | 0.638 | 0.665 |
| D1k lag-trigram key     | 216  | 0.563 | 0.559 | 0.513 | 0.513 |

Benchmarks vs. paper (our numbers vs. paper Table 1 / Fig 1):

- **Tricky Det (`_6`)**: paper reports BERT/LSTM/Transformer ≥ 0.997,
  Llama-1B 0.846, 2-gram baseline 0.821. Our **C1 LogReg** already
  reaches 0.997.
- **Tricky Random (`_9`)**: paper reports $\text{AUC}^\*=0.67$; best
  encoder 0.671, best decoder (Qwen-14B) ≈ 0.67, Llama-1B 0.587,
  2-gram 0.585. Our **C1 LogReg** = 0.671, matching the ceiling.

**Implication.** The paper’s “$k$-gram baseline” is contiguous
bigrams; these mix information across *different* offsets, diluting
the signal. A lag-$λ$ aware aggregated bigram ($λ=7$) saturates both
Tricky tasks with a *linear* classifier — even without access to
which letters are keys. Adding the $\kappa$ ordering as a hard
constraint (C1k, 36-dim) actually *hurts* performance on `_6` because
the relevant information also lives in correlations with non-key
letters.

### 3.2 Sparse C2 position-aware lag-pair

C2 (8 788-dim sparse CSR, each test sequence fills ~13 non-zeros)
returns AUC 0.996 / 0.996 on `_6` (LogReg / XGB) and 0.638 / 0.665
on `_9`. **C2 is no better than C1.** On `_9` it is strictly worse
because the position-aware features add noise without additional
signal. So: aggregation across positions is the right representation,
and the label truly depends on pair *counts*, not on *which positions*
the pairs occupy.

## 4. Matched-histogram counterfactual (Phase 3)

See `results/phase3_matched_histogram.csv`.

### 4.1 Full 26-dim histogram grouping is vacuous at this scale

With $n=20$, $\ell=26$ and 50 K test sequences, *every* 26-dim count
vector is unique in the test split: `n_ambig_groups_full26` = 0, so
all “full26_ambig” and “full26_balanced” AUCs are `NaN`. The paper’s
Table 2 (“94–96 % of sequences fall into ambiguous key-letter count
groups”) groups by the 6-dim **key-only** count vector, not the full
26-dim histogram.

### 4.2 Key-letter histogram-matched (`_9`)

For `_9`, 48 150 of 50 000 test sequences fall in a key-count group
that contains both labels:

| family | dim | standard AUC | key6_ambig AUC | key6_balanced AUC |
|---|---:|---:|---:|---:|
| A1 count26 | 26  | 0.584 | 0.568 | 0.500 |
| B residue  | 182 | 0.582 | 0.574 | 0.517 |
| **C1 lag-pair** | 676 | **0.669** | **0.665** | **0.647** |
| C1k key-only | 36  | 0.628 | 0.622 | 0.611 |
| C2 sparse  | 8788| 0.638 | 0.633 | 0.619 |

Content (A1) collapses to chance in the balanced-within-group regime,
but **C1 lag-pair keeps AUC 0.647** after matching on key-letter
counts and balancing labels within each group. So the pair-at-lag
signal is not explained by the key-letter count vector.

### 4.3 Caveat — full-26 matching at this scale needs larger N

To get non-trivial ambiguity on the full 26-dim histogram we’d need
a test split large enough to contain duplicates — roughly $N \gg \ell^{H_\text{eff}}$ with $H_\text{eff}$ the effective token entropy. For $(n,\ell)=(20,26)$, $N$ would need to be $10^{20}$-order. The matched-histogram test in the paper’s Table 2 is really a **key-only** matched test; we reproduce that result, and the C1 vs. A1 delta confirms that order at lag $\lambda$ — not letter identities — drives the C1 advantage.

## 5. Held-out-rule generalization (Phase 4)

See `results/phase4_heldout_rule.csv`. We sample 6 random rules
$(S,\kappa,\lambda)$, λ ∈ {5,…,9}, $m=6$, $n=20$, 20 K sequences
each labelled with `rule_pair_any_lag`. Each family is trained
leave-one-rule-out, evaluated both on the held-out rule (off-rule)
and on a held-out split of the same rule (on-rule).

| family | dim | AUC_on (avg) | AUC_off (avg) |
|---|---:|---:|---:|
| A1 count26    | 26   | 0.77 | 0.49 |
| B residue     | 156–234 | 0.77 | 0.49 |
| **C1 lag-pair** | 676 | **1.00** | **0.50** |
| C2 position   | 7.4 K – 10.1 K | 0.99 | 0.50 |

**Reading.** C1 lag-pair features linearise *each* rule perfectly
(AUC_on = 1.0) but carry no information across rules (AUC_off ≈ 0.5).
This is exactly the signature of “the task = pick a linear weighting
over 26×26 lag-pair counts per rule”. A model that learnt a
meta-procedure independent of $(S,\kappa,\lambda)$ would have
AUC_off > 0.5. Our 1 M-row experiments show no such transfer —
consistent with the paper’s own finding that the paper randomises
$\kappa$ “to avoid coincidental alignment with alphabetical order.”
That randomisation is exactly what breaks transfer for the baseline
too. So the “global sequence integration” interpretation of strong
neural performance is not supported: the neural models are also
learning per-rule weightings, not an algorithm.

## 6. Parity decomposition (Phase 5, Q3)

See `results/phase5_parity.csv`. 400 K training rows, 50 K test.
Model = LogReg (lbfgs) and MLP with one hidden layer of 64 units
and early stopping. Input variants:

| input | dim | LogReg AUC | MLP-64 AUC |
|---|---:|---:|---:|
| (A) hidden letters one-hot per position      | 520 | 0.504 | 0.502 |
| (A) hidden 26-dim count vector               | 26  | 0.504 | 0.500 |
| (B) **known K: membership bits** $b_t\!=\!\mathbf{1}[X_t\!\in\!K]$ | 20  | 0.501 | **0.997** |
| (C) known K: 6-dim per-key counts            | 6   | 0.507 | 0.997 |
| (C) known K: 6-dim per-key parity bits       | 6   | 0.504 | **1.000** |
| (D) known K: scalar total key count          | 1   | 0.500 | 0.981 |

**Reading.** With raw letters (regime A) everything stays at chance —
the paper’s central parity finding. But revealing only *which
positions are in $K$* (regime B, a 20-dim vector that does not
identify the individual key letters) is enough for a tiny MLP to
reach AUC 0.997. So the bottleneck is **hidden-subset
identification**, and the “failure to compute parity” story in
the paper overstates the difficulty: the architecture and
supervision used *can* learn parity from a 20-bit input in under a
minute. The task asks the model to *jointly* infer K, filter
distractors, and compute modular parity from end-to-end supervision,
which is strictly harder than any single piece.

### 6.1 Alphabet × subset-size sweep (balanced $p=1/2$)

Phase 5 also sweeps $\ell\in\{4,8,12,16,26\}$, $m=\ell/2$, $n=20$.
All hidden-input variants stay at chance, consistent with
Theorem 3.3 (the paper’s $k$-local purity result for $p=1/2$).
Curriculum and architecture sweeps we did **not** run — the paper’s
“Limitations” paragraph already concedes this — so our statement is
limited to end-to-end supervised LogReg/MLP-64.

**Reading.**

- `_9` oracle AUC 0.670 and F1 0.578 **match the paper’s claimed
  ceiling $(0.67,\,0.58)$** to three decimals. The retained /
  balanced sampling in `test_simulation_*.py` does not break this
  ceiling.
- `_6` **contradicts the paper claim of $\pi=0,\,\text{AUC}^\*=F_1^\*=1$**.
  No deterministic rule in the tested family reaches 1.0. The best
  reaches F1 0.854 / AUC 0.904. Either the generator used a rule
  I have not enumerated, or the labels are noisy
  ($\pi\!\approx\!0.12$–0.17). Phase 2 showed the labels are nearly
  deterministic in C1 feature space (LogReg AUC 0.997), so the rule
  exists — but the paper’s stated rule + S + κ is not it.
- Parity oracle is trivially 1.0 using impl S.
- **Model F1 > claimed F1\*?** Paper Table 1 claims $F_1^\*=1$ for
  `_6`; our oracle with the tested rules caps at $F_1=0.854$. Any
  model on `_6` that scores $F_1 > 0.854$ must either be learning
  extra per-sample information (leakage, data-split contamination) or
  the paper’s ceiling is the wrong ceiling for the generator actually
  used. Table 1 also lists `BERT F_1 \approx 0.99` for Tricky Det.,
  which is perfectly consistent with the true rule being some richer
  function of lag-pair counts (C1 LogReg reaches AUC 0.997, F1 0.992).

## 8. Recommended paper positioning

### 8.1 Claims supported **today** (→ smaller honest paper)

- **“Encoder-based architectures learn hidden fixed-lag skip-pair
  rules more data- and parameter-efficiently than decoder-only
  models; under symmetric label noise the efficiency gap widens but
  vanishes at sufficient scale.”** This is the strongest claim the
  current evidence supports. Every reported number — encoder ≥ 0.99
  on Tricky Det., decoder-only plateau at 1B, recovery at 14B — is
  intact.
- **“Parity with end-to-end supervision and tokens drawn from a
  large alphabet is hard because of hidden-subset identification,
  not because of modular computation.”** With the Phase-5
  decomposition table (§6), this is directly supported.
- Theorem 3.3 (local information leakage) and Theorem 3.5 ($k$-local
  purity of balanced parity) are theoretical; they are not affected
  by the generator discrepancy.

### 8.2 Claims **not** supported

- **“The tested encoders solve Tricky *beyond local shortcuts*.”**
  A 676-dim linear classifier on aggregated $\lambda$-shift bigrams
  saturates the task, hitting the noise ceiling exactly. The
  encoder-vs-decoder gap therefore lives **inside** the space of
  lag-aware local shortcuts. The paper’s contiguous-bigram baseline
  is the wrong comparator; a λ-aware bigram should be the
  baseline. Using that baseline, every encoder merely matches it.
- **“Tricky is an instance of global sequential integration / pure
  sequential dependence (Def. 3.1).”** The task is literally linear
  in lag-pair counts (AUC 1.0 on every synthetic instance in the
  held-out-rule test). Rephrasing as “hidden fixed-lag pair-rule
  learning” is both accurate and sells better.
- **“Parity tasks are unlearnable by current transformers.”** Once
  $K$ is revealed, parity is trivial. The paper’s limitations
  paragraph already says as much; §6 shows that a 20→64→1 MLP
  suffices.

### 8.3 Stronger redesigned paper (Branch B, if wanted)

If the author wants to *keep* a global-integration claim, the task
needs a rule that genuinely resists all linear lag-pair features. A
minimal patch:

- **Strict order**: replace $\kappa(X_{t_1})\!\le\!\dots\!\le\!\kappa(X_{t_k})$
  with strict $<$, and use a non-total order so that aggregated pair
  counts can contain both $+$ and $-$ evidence.
- **Minimum chain length $L\ge 4$**: pick $n$ and $\lambda$ so that
  $L=\lceil n/\lambda\rceil \ge 4$. At $\lambda=4$ and $n=20$ we get
  $L=5$ possible positions. A length-4 chain cannot be expressed as a
  single pair count.
- **Position-varying lag** (λ_j sampled from a hidden schedule) so
  that no fixed-λ feature family works.
- **Distractor interaction** — e.g. Y=1 iff the *last* compliant chain
  has length ≥ L — so that “exists pair” features leak much less.

A pilot (Section 5 of the plan) could run the same Phase 2 ladder on
this stricter task and show that: (i) C1 lag-pair linear models stay
well below the ceiling, (ii) C2 position-aware features close only
part of the gap, and (iii) encoder models still solve it, but now the
gap is a genuine *sequential-integration* gap.
