# Datasets

Three task variants (plus a sanity-check), all generated by the scripts in `src/generators/`.

| Tag | Variant | N_train | n | rho (positive rate) | lambda | pi (label noise) | m (key-set size) |
|---|---|---|---|---|---|---|---|
| `6` | Tricky Deterministic | 400K | 20 | 0.293 | 7 | 0 | 6 |
| `9` | Tricky Random | 400K | 20 | 0.293 | 7 | 0.3 | 6 |
| `test_just_pair` | Parity | 400K | 20 | 0.499 | -- | 0 | 6 |
| `alph` | Naive sanity check | 400K | 20 | -- | 1 | 0 | 26 |

Each dataset comes split 80/10/10 into train / validation / test, stored as 6 CSV files: `{X,y}_{train,val,test}_<TAG>.csv`. Tokens (uppercase letters) are joined with the unit separator `\x1f` in each row of `X_*.csv`. Labels in `y_*.csv` are binary.

Vocabulary: A-Z (26 uppercase letters). Hidden subset for Tricky tasks: S = {W, D, Q, J, X, U} with kappa(W) < kappa(D) < kappa(Q) < kappa(J) < kappa(X) < kappa(U). Hidden subset for Parity (in code): K = {W, D, Q, J, X, N}.

**Note on Parity subset**: the paper text (Section 4.1) describes the Parity hidden subset as {W, D, Q, J, X, U}, but the dataset shipped here and the generator code in `src/generators/test_simulation_det.py` use {W, D, Q, J, X, **N**}. The two choices have the same combinatorial structure (any size-6 subset of a 26-letter alphabet) so the empirical findings on hidden-subset parity are unchanged, but if you regenerate from `src/generators/` you will get the {N} variant. The mechanism-ID audit and the parity-decomposition results in the paper are computed with the {N} variant; this discrepancy is documented in `src/analysis/mechanism_id/report.md`.

Total ~62 MB on disk.
